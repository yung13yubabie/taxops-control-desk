Source access and single-EXE recombination
===========================================

Selected network source-delivery route
-------------------------------------
For this candidate's network download, the selected route is network access
under GPLv3 section 6(d) for the LGPL-covered library object code. The separate
combined-work mechanism is LGPLv3 section 4(d)(0): accompanying Application
Code and build materials suitable for recombining with modified libraries. These are different requirements; this is not
an "LGPL section 6(d)" procedure and does not select GPL for TaxOps itself.

The binary download's description must link directly to this SOURCE_ACCESS.txt
at the same TaxOps source revision and identify the bundled Qt/PySide/Shiboken
version as 6.10.2. The repository's docs/third_party_licenses.md provides the
same directions beside the candidate documentation. Recipients can download
the matching source archives below at no additional charge; they do not have
to download source just to obtain the application. These notices are embedded in the single EXE and available from the offline
Third-party licenses viewer/export. Supply the matching recombination kit
beside each binary download and preserve its RECOMBINE_PERMISSION.txt.

Build inputs and local changes
------------------------------
The normal build collects the official 6.10.2 Windows x64 PyPI wheels recorded
by URL/SHA-256 in manifest.json. It removes an unused VirtualKeyboard plugin
and stages the fixed Microsoft redistributable separately without modifying
installed wheels. The recombination demonstration makes actual source changes:
PySide6/support/__init__.py receives TAXOPS_RECOMBINE_MARKER, and Qt's gif.json
receives TaxOpsRecombineMarker before a real qgif.dll source compile. Exact
changes, source hashes, CMake inputs and executable probes are supplied in the
version-matched kit. These demonstration changes are not claimed as performed
in an ordinary build unless its receipt and frozen probes prove them.

Use Windows x64 Release shared libraries and Qt/PySide 6.10.2 interfaces.
TaxOps uses CPython 3.11.9 and the bindings' stable-ABI cp39-abi3 Windows wheels.
Keep compatible dependent DLLs together; do not use debug, ARM64 or static
libraries without adapting and revalidating the complete build.

The fixed-version source distributions include build scripts, headers and
configuration logic. Relevant upstream instructions and scripts are:

Qt Windows build guidance and configure options, tag v6.10.2:
https://github.com/qt/qtdoc/blob/v6.10.2/doc/src/platforms/windows.qdoc
https://github.com/qt/qtdoc/blob/v6.10.2/doc/src/configure.qdoc
Qt module configure/CMake inputs:
https://github.com/qt/qtbase/blob/v6.10.2/configure.cmake

Use the 6.10.2 sources even where the upstream guide illustrates another
version. The Windows guide specifies MSVC2022 and a compatible Qt build;
Shiboken generation also needs libclang. The source README documents setup.py
build, --qtpaths, --limited-api and --module-subset. Its COIN script records
--standalone, --unity and --limited-api=yes. Qt PDF's source configuration sets
use_custom_libcxx=false and use_partition_alloc=true. These are published build
inputs, not a recovered log of the precise vendor wheel invocation.

The vendor's generated CMakeCache.txt, complete GN args and wheel build log
were not recovered. No extra vendor patch is identified. TaxOps demonstration patches and their
rebuild harness are supplied. Successful Windows compilation and actual frozen
replacement execution must be evidenced for the version being distributed. These are the specific reproducibility/validation limits;
bit-for-bit reproduction is not claimed and is not used as an indefinite
source-delivery blocker. If a different source revision or an additional
necessary vendor patch is discovered, update these directions and provide it
before presenting that library's corresponding source as complete.

Recombining the single EXE (LGPLv3 section 4(d)(0))
-------------------------------------------------
The ordinary user receives one EXE. It contains all application runtime files;
Qt libraries are extracted temporarily by the standard PyInstaller bootloader.
The recipient does not have to replace files inside a transient _MEIPASS folder.

The accompanying exact Application Code kit includes source, spec, hooks,
assets, all 28 migrations, pins, source hashes, original notices,
BUILD_RECOMBINE.txt and the limited RECOMBINE_PERMISSION.txt. Its executable
build_tools.recombine script creates isolated environments, compiles and stages
modified Qt/PySide components, and builds a new standard single EXE. Refer to
BUILD_RECOMBINE.txt for prerequisites and the complete command. No external DLL
loader, publisher key, signature bypass or online activation is required.

Use a test Windows account and synthetic data. Run the entire regression/90%
branch coverage gate and all actual EXE checks. A report marker without the
modified module executing, or without real qgif metadata and GIF decoding,
is not recombination evidence. The supplied build checks are not runtime
restrictions on exercising the recipient's LGPL permissions.

The included LGPL/GPL texts describe the rights applicable to the covered
libraries, including modification and reverse engineering for debugging such
modifications. Nothing in this notice index removes those rights. The final
application's terms must remain compatible with them.

Maintaining the network route (GPLv3 section 6(d))
-------------------------------------------------
The download publisher must keep clear source directions next to the binary
and equivalent no-additional-charge copying access. Source may be hosted by
Qt or another server, but the distributor remains responsible for its
availability for as long as required by section 6(d). Recheck the URLs when
publishing a candidate or release. If hosting disappears or access ceases to
be equivalent, restore access to the same matching source (for example by a
permitted mirror) before continuing to rely on that route. Do not silently
replace a pinned source version with a newer release.

This selects an operational network route, not the written-offer alternative
in GPLv3 section 6(b). It creates no separate written source offer or commercial
agreement. An offline-only redistribution needs an applicable source-delivery
route of its own; a paper promise is not supplied here. Microsoft runtime
provenance/terms questions are separate and remain recorded in manifest.json.
