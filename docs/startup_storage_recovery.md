# 啟動時無法開啟資料

若資料夾、資料檔或磁碟無法讀寫，程式會停止啟動，顯示「無法開啟資料」。
主視窗不會以空白資料繼續開啟，也不會因此刪除、覆蓋或自動重建原資料庫。
按「確定」或 Esc 關閉提示；處理原因後，再重新開啟程式。

這是錯誤處理不替換原資料的承諾，不是損壞修復或任意磁碟故障後的逐位元組保證。
若啟動已開始執行既有的資料版本更新，失敗中的單一更新依原本交易規則回滾，
較早成功的更新仍會保留；SQLite 自身也可能更新檔案標頭或頁面。
磁碟已受損時應先保留原始檔案，不能把顯示錯誤提示視為資料已驗證完好。

## 依提示處理

- **儲存空間不足：** 先騰出資料所在磁碟的空間。不要刪除 TaxOps 的資料檔、
  附件或唯一備份來騰出空間。
- **無法寫入資料夾或資料檔：** 確認目前帳號對資料夾有讀寫權限，且磁碟不是唯讀。
  不確定時請聯絡電腦管理人員；不要為了啟動程式而開放所有人的存取權限。
- **資料檔忙碌：** 關閉其他正在使用同一份資料的程式，稍候重試。
- **資料檔可能損壞或格式不符：** 先另外保留整份原始資料目錄與附件，請維護人員
  檢查。需要復原時使用已確認可用的備份。此提示不代表程式已修復損壞；重複啟動
  也不會自動修復或替換資料檔。
- **其他讀寫失敗：** 確認磁碟可正常使用、空間足夠且資料夾可讀寫。仍失敗時，
  請提供提示內容及可用的診斷紀錄給維護人員。

一般 Windows 資料目錄為 `%LOCALAPPDATA%\TaxOpsControlDesk`，資料檔是
`taxops.sqlite`，附件位於其中的 `attachments` 目錄。開發模式使用
`TaxOpsControlDeskDev`。請先關閉程式再另存原始資料；若有 `-wal`、`-shm`
等伴隨檔案，也應一併保留，不要只搬走單一檔案。不確定位置或如何復原時，
請由維護人員協助，避免覆蓋唯一的原始資料。

## 本機診斷紀錄

程式會嘗試在作業系統的暫存目錄建立唯一的 `TaxOps-startup-*.log`，只在寫入成功
時於提示中列出完整路徑。紀錄包含時間、例外種類、SQLite 錯誤代碼及技術堆疊，
不收集變數內容、資料庫紀錄或附件，也不會自動上傳。技術堆疊可能包含檔案路徑
及底層錯誤訊息，分享前請先檢查。

若暫存目錄也無法寫入，提示會明確顯示「診斷紀錄無法儲存」，原本的啟動原因
仍會顯示。建立後若寫入或關閉失敗，程式只嘗試清理這次未完成的診斷檔，不會
刪除既有或已成功儲存的紀錄。若清理也失敗，提示會列出可能仍保留的未完成檔案
路徑，明確說明它不是完整紀錄。請記下畫面供維護人員檢查。
暫存紀錄可能被系統清除，需要保留時請
自行另存；問題處理完可刪除對應的診斷紀錄，這不等於刪除資料庫或附件。

## 實作與驗收契約

- 只有啟動資料準備階段的 `sqlite3.Error` 與 `OSError` 使用這個處理流程。
  未知程式錯誤不會被轉成空資料或假稱可恢復。
- SQLite 連線建立後若初始化失敗，必須先嘗試關閉連線，再由啟動流程釋放自己
  持有的單一執行個體鎖。若連線關閉也失敗，保留原例外並在診斷中記錄清理失敗，
  不宣稱連線已成功關閉。
- `tests/test_startup_storage_errors.py` 使用合成資料、真 SQLite、真 Qt 對話框、
  鍵盤關閉及真原子檔案鎖，覆蓋損壞資料、精確讀寫故障注入、既有資料與附件
  位元組保留、同一資料目錄解除注入後重新啟動，以及診斷建立／寫入／關閉／清理
  失敗和既有紀錄保留。
- 已開始寫入的合成更新另驗證回滾後邏輯資料、更新紀錄與附件保留，檢查資料庫
  完整性，並移除注入原因後對同一份資料重試；不將這項結果寫成整個資料庫檔案
  逐位元組不變。
- 完整啟動與重試案例各自使用獨立程序，避免 Qt 結束狀態污染下一個案例；
  執行完整矩陣時，子程序 branch coverage 也併入相同 coverage pool。
- 這些測試只替換本機 socket activation，不把它算成 IPC 驗收。完整 IPC 測試仍由
  `tests/test_single_instance.py` 執行，失敗必須保留。沒有實際修改系統權限或填滿
  磁碟，也不能將 Linux offscreen 通過寫成 Windows 實機、DPI 或凍結版驗收。

完整逐檔測試與原有 90% branch coverage 門檻維持不變，見
[CONTRIBUTING](../CONTRIBUTING.md) 與 [Windows candidate gate](windows_candidate_gate.md)。
