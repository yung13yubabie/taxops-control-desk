# 年度申報工作台與客戶主檔擴充設計

日期：2026-07-13  
狀態：視覺方向與核心語意已由使用者核准，待實作計畫與開發  
目標版本：v0.30.0（暫定）

## 1. 目標

把 TaxOps Control Desk 擴充成真正可離線使用的事務所年度工作台，而非只新增展示畫面。正式功能必須寫入既有 SQLite、共用既有服務與稽核紀錄，並封裝進 Windows EXE。

本輪包含三組互相連結的能力：

1. 客戶主檔支援設籍地址、聯絡地址、多份租約及行業清單。
2. 新增獨立「年度工作台」，以每位客戶、每個作業年度為一個母體，追蹤申報、憑證、稅款、服務費及異常。
3. 工商／稅籍查詢顯示並搜尋既有離線快取中的主要與次要行業，且可選擇套用至客戶主檔。

## 2. 已確認的產品規則

### 2.1 年度與期間

- 每位客戶、每個作業年度最多一個有效年度母體。
- 「作業年度」與「所屬課稅年度／期別」是不同欄位，不得用一個年份取代。
- 客戶預設採曆年制；可設定特殊會計年度起始月份。
- 系統保存建議期限與實際採用期限；後者可人工調整。
- 客戶申報設定檔只作為新年度預設，不回寫或改造歷史年度。

### 2.2 產生與刪除

- 建立年度前先預覽預計工作，可取消不適用項目或加入自訂案件。
- 確認建立必須以單一資料庫交易完成。
- 重複點擊、重送或再次產生不得新增重複母體或重複工作。
- 尚無申報、金流、索件或回執實績的工作可刪除。
- 已有實績的工作可取消或標記不適用並恢復，不直接抹除稽核軌跡。

### 2.3 狀態

不得用單一「完成」代表所有責任均已履行。每筆工作分開保存：

- 作業狀態：未開始、處理中、已完成、異常、不適用、已取消。
- 申報狀態：未申報、已申報、申報失敗、需更正。
- 憑證狀態：未索取、缺件、部分收到、已齊、不適用。
- 稅款狀態：未確認、待代收、部分代收、已代收、已繳、欠繳、退稅、不適用。
- 服務費狀態：未開立、待收、部分收款、已收、不適用。

若仍有缺件、欠稅或未收款，使用者仍可結束工作，但系統顯示「帶異常完成」、要求原因，並持續列入風險總覽。

### 2.4 單機使用

- 本產品維持單機、單一使用者定位。
- 不新增員工、承辦人、覆核人、登入或權限欄位。
- 年度期限不自動複製成待辦；使用者可選擇建立連結待辦。

## 3. 年度預設工作

客戶申報設定檔可啟用下列標準工作：

- 每月帳務結帳與憑證收集。
- 營業稅（預設每兩月一期；可設定每月一期）。
- 每月扣繳稅款繳納。
- 年度扣免繳憑單。
- 營利事業所得稅結算申報。
- 未分配盈餘申報。
- 營利事業所得稅暫繳。
- 薪資、勞健保、勞退及補充保費（選用）。
- 公司年度事項及簽證需求（選用）。
- 自訂臨時案件，例如更正、補報補繳、退稅、稅局來函、查帳、工商變更、停歇業或決清算。

內建期限規則只提供建議值。特殊會計年度、法定展延或個案期限由使用者確認後保存實際採用期限。

## 4. 資料模型

### 4.1 客戶地址

在 `clients` 新增：

- `registered_address TEXT`
- `contact_address TEXT`
- `contact_address_same INTEGER NOT NULL DEFAULT 1`

升級時把既有 `address` 搬到 `registered_address`。舊欄位暫時保留以降低 SQLite 升級風險，但新程式一律以 `registered_address` 為正式來源；相容讀取只供舊資料升級。

工商資料預設只套用設籍地址，不覆蓋聯絡地址。

### 4.2 多份租約

新增 `client_leases`：

- `id`, `client_id`
- `lease_name`, `premises_address`, `landlord_name`
- `start_date`, `end_date`
- `monthly_rent`, `deposit_amount`
- `reminder_days`
- `status`, `notes`
- `created_at`, `updated_at`, `deleted_at`

同一客戶可有多份日期重疊的有效租約。既有 `lease_start`／`lease_end` 若有值，升級時建立一筆「既有租約」；遷移必須可重跑且不重複。

租約附件沿用既有受控附件目錄與檔案防護。`attachments` 需支援案件附件或租約附件兩種合法擁有者，並以資料庫約束避免無主附件。既有附件資料完整搬移，不改檔案實體位置。

### 4.3 客戶行業

新增 `client_industries`：

- `id`, `client_id`
- `industry_code`, `industry_name`
- `is_primary`, `sort_order`
- `source`, `source_version`, `applied_at`

套用工商資料時，以同一交易取代該客戶目前行業清單並寫入稽核。未選取行業欄位時不得清空既有資料。

### 4.4 申報設定檔

新增 `compliance_profiles`：

- `id`, `client_id UNIQUE`
- `fiscal_year_start_month`（1 至 12，預設 1）
- `created_at`, `updated_at`

新增 `compliance_profile_items`：

- `id`, `profile_id`
- `work_type`
- `frequency`
- `enabled`
- `notes`
- `created_at`, `updated_at`

標準工作類型使用穩定代碼；UI 僅顯示繁體中文名稱。設定檔變更只影響未來建立或使用者明確選擇補入的目前年度工作。

### 4.5 年度母體與工作項目

新增 `annual_workspaces`：

- `id`, `client_id`, `operation_year`
- `fiscal_year_start_month_snapshot`
- `status`
- `created_at`, `updated_at`, `deleted_at`

使用部分唯一索引確保同一客戶與作業年度只有一個有效母體。

新增 `annual_work_items`：

- `id`, `workspace_id`, `item_key`
- `work_type`, `title`
- `tax_year`, `period_code`
- `suggested_due_date`, `due_date`
- 五組獨立狀態欄位
- `engagement_id`（可選）
- `exception_reason`, `notes`
- `completed_at`, `cancelled_at`
- `created_at`, `updated_at`, `deleted_at`

`item_key` 對同一年度母體唯一。標準工作由類型、課稅年度及期別產生穩定鍵；自訂工作使用隨機穩定鍵。重跑產生器使用 insert-if-missing，不更新已由使用者調整的工作。

待辦使用 `workflow_tasks.annual_work_item_id` 可選外鍵建立關聯；一筆年度工作可有零至多筆待辦，不自動建立。

### 4.6 金流明細

新增 `annual_work_transactions`：

- `id`, `work_item_id`
- `category`
- `amount`（TWD 整數、非負）
- `transaction_date`
- `reference`, `notes`
- `created_at`, `updated_at`, `deleted_at`

類別包含：

- 申報／核定應納稅額
- 客戶代收稅款
- 實際代繳稅款
- 退稅或抵繳
- 服務費應收
- 服務費收款

系統分別計算：尚待向客戶代收、尚未代繳稅款及服務費未收。任何一個餘額不能代替其他餘額，也不提供直接編輯總額的欄位。

## 5. 與既有功能的整合

### 5.1 案件、索件與附件

- `annual_work_items.engagement_id` 是正式關聯，不複製案件資料。
- 年度工作台直接呼叫既有案件、索件與附件服務新增或編輯資料。
- 年度頁顯示索件批次、缺件項目、催收次數與附件數。
- 從年度頁或原索件頁修改的都是同一資料列；任一頁重新啟用時必須重新查詢。
- 新增案件後再新增索件若任一步驟失敗，年度工作連結不得留下半成品。

### 5.2 待辦

- 年度工作不自動建立待辦。
- 使用者可從年度工作建立一筆有正式外鍵的待辦。
- 完成年度工作不自動完成待辦；UI 提示仍有未完成連結待辦。

### 5.3 工商／稅籍查詢

既有 `tax_registry_cache` 已保存主要與三組次要行業。查詢服務擴充為：

- 統編精確搜尋。
- 公司名稱精確或部分搜尋。
- 行業代碼精確或部分搜尋。
- 行業名稱部分搜尋。

結果列表顯示主要行業；明細顯示全部行業。GCIS 單筆回應未提供行業時，UI 顯示「此來源未提供行業資料」，不得顯示為查無或自行補值。

## 6. 介面設計

視覺參考：`docs/annual-workbench-mockup.html`。

### 6.1 導覽

左側主導覽新增「年度工作台」，位於客戶管理之後、案件管理之前。它是日常主要入口；案件、索件與附件仍保留全域索引用途。

### 6.2 全所年度總覽

頂部固定顯示：

- 作業年度
- 客戶／統編搜尋
- 工作類型
- 風險篩選
- 建立年度工作與申報設定檔入口

摘要數字包含逾期、缺件、尚未代繳稅款、需更正與本月完成。摘要必須由實際資料計算，不得硬編碼。

主表至少顯示客戶、工作、課稅年度／期別、期限、憑證、申報、稅款、尚未代繳及作業狀態。點列後顯示完整明細與操作。

### 6.3 客戶年度明細

顯示該客戶所有年度工作，並可在同頁：

- 新增／編輯／取消／恢復工作。
- 新增或連結案件。
- 新增／編輯索件批次及缺件項目。
- 上傳、預覽、封存附件。
- 新增／修正金流明細。
- 建立選用連結待辦。
- 查看稽核與異常原因。

### 6.4 不裁切驗收

- 說明、錯誤、警告及空狀態文字完整換行，不設定會裁切文字的固定高度。
- 表格可橫向捲動；長文字格可省略，但必須有全文 tooltip 與明細顯示。
- 表單閱讀順序固定，不因寬度任意換位。
- 對話框內容使用捲動區，底部儲存／取消操作列保持可達。
- 實測 1366×768、1920×1080，Windows 100%、125%、150% 縮放。

## 7. 錯誤處理與防假成功

- 建立年度、整批產生、連結案件／索件與套用行業均使用交易。
- 所有建立操作在成功後重新讀取資料列並驗證 ID；找不到資料視為失敗。
- 唯一約束衝突轉成可理解訊息，並開啟既有年度，不顯示「新增完成」。
- 連點期間按鈕停用；服務層仍必須具備冪等性，不能只靠 UI 防重複。
- 期限與期間驗證失敗保留輸入並聚焦第一個錯誤欄位。
- 金額拒絕負數、非整數與超出 SQLite 安全範圍的值。
- 取消有實績的工作時顯示具體影響並要求原因。
- 資料庫或檔案失敗顯示繁體中文訊息、寫系統日誌與稽核，不暴露 raw exception。
- UI 成功訊息必須以重新查詢後的具體結果為依據。

## 8. 離線與資源限制

- 年度工作台、客戶主檔、租約、行業快照與金流完全離線可用。
- 只有現有 GCIS 單筆補查需要網路，且不是年度工作台必要條件。
- 大型工商名稱／行業搜尋沿用背景工作與有限逾時，不阻塞 UI。
- 背景執行緒由頁面持有直到結束，應用程式關閉時不得銷毀仍在執行的執行緒。
- 附件仍保存在本機受控附件目錄，SQLite 只保存受驗證相對路徑與中繼資料。

## 9. 驗證策略

### 9.1 自動測試

- 從 v0.29.0 結構升級，驗證地址與既有租約不遺失、不重複。
- 年度母體唯一約束、產生器冪等、重複點擊與交易回滾。
- 曆年制與特殊會計年度的期間及建議期限。
- 五維狀態、帶異常完成與恢復。
- 多筆代收、部分代繳、退稅／抵繳、服務費部分收款的餘額。
- 工作與案件／索件／附件的雙向一致性。
- 既有索件頁修改後年度頁重新查詢可見，反向亦同。
- 行業代碼／名稱搜尋、全部行業顯示與選擇性套用。
- 無行業 GCIS 回應顯示來源未提供，不偽造資料。
- 租約重疊、到期提醒、取消與歷史保留。
- UI 透過實際按鈕與對話框路徑驗證，不直接呼叫私有 helper 取代使用者操作。

### 9.2 覆蓋率

- 以 `pyproject.toml` 現有 branch coverage 與 `fail_under = 90` 為硬性門檻。
- 不以 `omit`、大範圍 `pragma: no cover`、跳過新模組或只測成功路徑維持數字。
- 覆蓋失敗回滾、重複輸入、刪除限制、缺少關聯、未知狀態及 UI 錯誤提示分支。

### 9.3 完整交付鏈

依序執行：

1. migration／compile 檢查
2. 相關單元與整合測試
3. 全測試與 branch coverage ≥ 90%
4. 實際 PySide6 使用者路徑 smoke
5. 1366×768 與高 DPI 不裁切驗證
6. 資源清理檢查
7. PyInstaller 重建 Windows EXE
8. 隔離 `LOCALAPPDATA` 的 EXE 啟動與 SQLite 建立 smoke
9. 產出 ZIP、SHA-256 與人工驗收清單

任何一步失敗都以失敗回報，不得以舊 EXE 或預期可行代替證據。

## 10. 非目標

- 不新增雲端同步、多人登入、權限或 SaaS 後端。
- 不替使用者自動向政府網站送出申報或付款。
- 不把 GCIS 網路查詢變成大量爬蟲。
- 不用年度工作台取代所有案件、索件、附件與待辦頁；它是整合操作入口。
- 不在本輪建立完整總帳、薪資計算引擎或銀行串接。
